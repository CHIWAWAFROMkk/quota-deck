# QuotaDeck HUD 子项目 3：刘海胶囊、额度光晕与游戏时安静 设计

日期：2026-10-21 · 状态：待用户审阅 · 基于 `main`（`9b46c83`，0.6.0）

## 1. 意图

用户在 Windows 上看视频（经常全屏）时，希望用余光瞄一眼屏幕顶部正中，就知道几家额度的情况、有没有 agent 在跑、哪家做完了或在等批准，不用去找贴在边上的浮条。外观照 Agent HUD 视频 25 秒那个黑色"刘海"胶囊加彩色光晕。

**打游戏时不要任何打扰**（用户明确说明）：整个 HUD 都安静，提醒攒着，退出游戏后再出现。

背景：用户过两天换到 Mac 上工作，这台 Windows 以后"偶尔还会用"。用户要求先在 Windows 上做完，Mac 的事到了 Mac 再说。所以本设计只针对 Windows，不为 Mac 做任何准备。

## 2. 目标、非目标、反目标

**目标**
1. 新的显示方式"刘海"：屏幕顶部正中一块黑色胶囊，外面一圈按额度着色、会呼吸的光晕。
2. "做完了"、"在等你/批准"时，黑块向两侧长出翅膀显示提醒，点一下打开现有卡片。
3. 鼠标停上去，黑块稍微变宽，露出五家的圆环，不显示数字（**用户在样稿里选了 B**）；点某一家，打开这家现有的卡片。
4. 打游戏时整个 HUD 隐藏，包括刘海、贴边浮条、提醒胶囊和卡片；退出游戏后恢复，攒下的提醒照常出现。
5. 全屏看视频（浏览器、播放器）时 HUD 照常显示。

**非目标**
- Mac 版、真实硬件刘海适配。
- 原版那块 540 宽的总览面板。用户选择沿用现在"点哪家看哪家"的卡片。
- 原版光晕的其他画风（Dots / ASCII / Blocks 等）和效果（Flow / Scan 等）；光晕的亮度、范围等设置项。
- 拖动刘海。它固定在顶部正中。

**反目标**
- 打游戏时 HUD 出现或闪烁。这是用户明确不要的。
- 全屏看视频时 HUD 消失。这样功能就失去意义了。
- 把提醒在游戏期间丢掉，而不是攒着。

## 3. 约束

- Windows 11，Electron 44，沿用现有 HUD 架构：主进程算数据，渲染层只负责显示；CSP 不允许内联样式，只能用 CSSOM；不新增 npm 依赖。
- 刘海和贴边浮条**二选一**，同一时间只显示一种。
- 复用现有的数据和组件：`hud:state`（额度圆环和档位）、`hud:sessions`（在跑、提醒）、批准请求（2b），以及现有的额度卡片、提醒卡片、批准卡片。
- 文案英文，与现有 HUD 一致。
- 分工（用户长期偏好）：后端（`src/main/**`）交给 GPT，前端（`src/renderer/**`、preload、冒烟脚本）由 Claude 写并协调合并。GPT 额度不够时，按用户以往的决定由 Claude 补上。

## 4. 外观与行为（数值取自原版源码）

**收起**
- 位置：HUD 所在显示器工作区的顶部正中，紧贴上边缘。
- 尺寸：宽 200，高 30。下方两个圆角半径 12；上方两侧有"耳朵"，用凹形曲线过渡到屏幕边缘，半径 8。
- 纯黑、不透明。里面**什么都不显示**。

**光晕**
- 形态：贴着黑块两侧和下方的一圈柔光。向外延伸 14，模糊 8，亮度 0.9，只向外发散，伸出屏幕的部分被截掉。
- 颜色表示额度：按 HUD 顺序（Codex、Claude、Antigravity、WorkBuddy、DeepSeek），每家一个渐变色标，位置在 (i + 0.5) / n。颜色与浮条圆环的档位色一致：`#3ddc84` / `#ffd23f` / `#ff453a`。没有读数的那家是 `#9a9aa0`；如果全部没有读数，整圈灰色，不呼吸，透明度 0.35。
- 呼吸：透明度在峰值和峰值 × 0.4 之间往返。有会话在跑时周期 3 秒，都闲着时 7 秒。
- 事件闪光：有新提醒时，只让那一家对应的那一段闪一次，共 1.8 秒。New reply 用 `#82aaff`；Waiting、批准请求和出错用 `#e9a16d`。

**提醒翅膀**
- 有提醒时，黑块向两侧扩展：宽 = 200 + 2 × (112 + 16) = 456，高 38，下方圆角 14。
- 左翼：bot 脸（17 px）加厂商名（13 px 半粗）。
- 右翼：`New reply` / `Waiting` / `Stopped`，同一家有多条时加 `×N`。
- 多家同时有提醒：翅膀里显示最需要处理的那一条，优先级为 批准 > Waiting > Stopped > New reply；同级取最新的一条。
- 点翅膀，打开这一家的提醒卡片或批准卡片（现有的）。
- 提醒的存留规则沿用 2a（看过才消失），不学原版 4 秒后收起。
- 卡片挂在黑块正下方，间距 6。

**鼠标停上去（样稿 B）**
- 停 400 ms 后，黑块变宽，露出五家的圆环：只有圆环和 logo，没有数字，尺寸沿用浮条的 size 和 ringWidth。
- 离开 200 ms 后收回。展开和收回用 `cubic-bezier(.2,.8,.2,1)`，400 ms。
- 点某个圆环，打开这一家的卡片（有提醒时开提醒卡片，和现在浮条的规则一样）。
- 有 agent 在跑时，圆环里的 logo 换成 bot 脸，和浮条一样。

**设置**
- 设置页 Display 里新增 `Style: Strip / Notch`，默认 `Strip`，即现有的贴边浮条。切换后立即生效，并持久化。
- 选 `Notch` 时，贴边浮条和它的提醒胶囊都不显示；Size、Show rings 这些设置仍作用于刘海展开后的圆环；Show numbers 对刘海没有影响。

## 5. 游戏时安静

**判定为"在打游戏"（满足任一条）**
1. Windows 报告有程序在独占全屏运行 Direct3D（`SHQueryUserNotificationState` 返回 `QUNS_RUNNING_D3D_FULL_SCREEN`）。
2. 前台窗口覆盖了它所在的整块显示器，而且它的程序路径在 Steam 游戏库里（路径包含 `\steamapps\common\`）。
3. 前台窗口覆盖了整块显示器，而且程序名在游戏名单里。名单存在 HUD 设置文件里，键为 `games`，是一组 exe 文件名，不区分大小写。默认值取自用户本机已安装、但不在 Steam 游戏库里的游戏（2026-10-21 核对过桌面快捷方式）：
   - `cs2.exe`：完美世界竞技平台的 CS2 装在 `D:\SteamLibrary\perfectworldarena`
   - `tlou-ii.exe`、`tlou-ii-l.exe`：The Last of Us 2，装在 `D:\SEED`
   - `javaw.exe`：Minecraft，经 Plain Craft Launcher 启动；只有占满全屏时才算

   界面上暂不提供编辑；用户可以手改设置文件。设置的读取和保存都必须保留这个键（现在的 `normalizeHudSettings` 会丢掉不认识的键，要一起改）。

浏览器和视频播放器即使全屏，也不算游戏，HUD 照常显示。用户全屏看视频用的是 **Edge 里的 B 站**。浏览器全屏不是独占全屏，不会触发规则 1。

**置顶**：Edge 全屏时，刘海必须仍在最上层。实现要验证这一点；如果会被盖住，就提高置顶级别，或在进入、退出全屏时重新设置置顶。这一项列入手动验收。

**安静时**
- HUD 窗口整个隐藏，包括刘海、浮条、胶囊和卡片，也不弹出任何东西。
- 会话监视、批准服务照常运行，提醒照常攒着。
- 批准请求不能因为玩游戏而被吞掉：钩子照常等待；等待超时后，按 2b 的现有规则交回给终端里的原生提示。
- 退出游戏（以上条件都不再满足）后约 2 秒内，HUD 恢复显示，攒下的提醒照常出现，光晕补闪一次。

**检测方式**
- 主进程起一个常驻的 PowerShell 小进程：用 `Add-Type` 调用 user32 / shell32，每 1.5 秒检查一次，只在状态变化时输出一行 JSON（`{"gaming":true,"exe":"cs2.exe"}`）。
- 这个小进程退出了就自动重启，一分钟内最多重启 3 次。完全起不来时，就当作"没在打游戏"，照常显示 HUD。
- 不新增 npm 依赖，不用原生模块。

## 6. 已由用户决定

| 问题 | 决定 |
|---|---|
| 用途 | 看视频时用余光看状态 |
| 打游戏 | 整个 HUD 安静，提醒攒着，退出游戏后再出现 |
| 鼠标停上去 | 不要原版的总览大面板，沿用现在"点哪家看哪家"的卡片 |

| 怎么认游戏 | 独占全屏，或者 Steam 游戏库里的程序全屏（用户平时从 Steam / 5E 启动游戏），再加一个可手改的名单 |

| 全屏看视频用什么 | Edge 里的 B 站 |
| 有没有不走 Steam 的游戏 | 有：完美世界 CS2、The Last of Us 2、Minecraft，已放进默认名单 |

## 7. 我替用户做的决定（请过目）

- 刘海和贴边浮条二选一，设置里切换，默认仍是贴边浮条。
- 光晕颜色照原版表示额度，不表示会话状态；会话状态通过呼吸快慢和事件闪光体现。
- 提醒翅膀沿用 2a 的规则，看过才消失；多家同时有提醒时，只显示最需要处理的那一家。
- 刘海固定在 HUD 所在显示器的顶部正中，不能拖动。
- 游戏名单先只放在设置文件里，不做编辑界面。
- 游戏检测用常驻 PowerShell 小进程，不引入原生模块。
- 这台电脑只有一块 1920×1080 的显示器，所以只要在打游戏，整个 HUD 就隐藏，不区分在哪块屏。
- 翅膀展开时鼠标停上去：翅膀先收起，换成圆环；鼠标离开后翅膀回来。
- Size 调大时，刘海展开后的高度跟着圆环变高（圆环 + 上下各 4），不缩小圆环；收起时仍是 200 × 30。
- 进入游戏时，已经打开的卡片直接关掉；用户之前在托盘里手动隐藏 HUD 的状态，不因为进出游戏而改变。

## 8. 留给实现的人

- 光晕的具体画法：CSS 渐变加模糊，或者 canvas 都可以，但要满足第 4 节的数值。
- 刘海窗口：可以复用现有 HUD 窗口，在"刘海"模式下重新布局，也可以单独开一个窗口。要保证穿透判断、置顶和崩溃恢复和现在一样可靠。
- PowerShell 检测脚本的写法、它和主进程之间的协议细节。
- 测试怎么组织：
  - 单测覆盖光晕色标的计算、翅膀里选哪条提醒、游戏判定规则（用假的检测结果驱动）、设置项校验。
  - 冒烟覆盖刘海的收起、停上去展开、翅膀、点圆环开卡片、模式切换，以及模拟进入、退出游戏时窗口的隐藏和恢复。
